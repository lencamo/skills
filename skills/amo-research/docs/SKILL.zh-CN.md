# amo-research

## 元数据

- name: `amo-research`
- description: 当用户要求调研竞品、社区或开源项目如何实现某项功能，寻找成熟可复用方案，或通过外部证据验证实现选项以辅助方案判断时使用。不用于泛市场分析，也不用于不涉及外部实现调研的方案设计。

# Amo Research

调研别人如何实现相关能力、为什么其方案适合其场景，以及当前项目可以复用什么。

## 共享输出标记

首行内联前缀使用 `🔬 [amo-research]`。不要把该标记单独放在一个段落里。

## 使用场景

- 用户希望了解竞品、社区或开源项目如何实现相关功能。
- 实现选择需要外部证据，或用户希望在自行构建前确认是否已有成熟替代方案。
- 外部实现调研能够辅助 `amo-feature`、`amo-improve`、`amo-fix`、`amo-refactor` 或 `amo-best` 做方案判断。

## 不使用场景

- 用户只需要方案设计、问题诊断或方案复核，不涉及外部实现调研。
- 任务是泛行业、市场或营销导向的竞品分析。
- 用户要求编码实施或审查已实现代码。

## 工作流

1. 明确实现问题、项目背景、已有判断标准及候选方案。
2. 按需从竞品、开源项目、官方文档或社区讨论中寻找可比实现。
3. 查看相关源码、文档、issue 或维护者讨论，解释实现机制、适用条件和取舍。
4. 根据项目适配程度及改造成本，评估直接采用、复用局部代码、借鉴设计或放弃候选方案。
5. 推荐复用方案，说明对当前决策的影响、仍需验证的问题及证据缺口。

## 核心规则

- 实际查看来源；记忆和搜索摘要不算已验证的调研。
- 优先一手证据，在结论附近附链接；可获取时标明源码版本。
- 区分事实、推断和建议，不凭可见行为断言内部架构。
- 按实际使用、维护和限制判断成熟度，不只看热度；推荐代码或依赖前核对版本和许可证。
- 评估项目适配程度及复用成本，不引入多余架构。
- 证据充分或检索无新增信息时结束；说明不确定性，不声称已穷尽所有实现。
- 只做调研，不修改代码、安装依赖或自动调用其他 skill。
