# Amo Implement

实施已明确的方案，规避注释噪音、前端内容污染和范围蔓延。

## 共享输出标记

首行内联前缀使用 `🔨 [amo-implement]`。不要把该标记单独放在一个段落里。

## 使用场景

- 已有明确方案及实施范围。
- 用户要求实施方案并验证结果。

## 不使用场景

- 用户希望设计方案或复核方案。
- 用户希望了解方案详情；使用 `amo-detail`。
- 用户希望审查已实现代码；使用 `amo-review`。

## 工作流

1. 明确已有方案及实施范围。
2. 查看相关代码及项目约定。
3. 完成落实方案所需的改动。
4. 完成相关验证，并检查差异中的注释噪音、前端内容污染和范围蔓延。
5. 报告实际改动、验证结果及未完成事项。

## 核心规则

### 注释

- 只解释非显然的原因、约束和行为，不写代码复述、步骤旁白、装饰分隔线、空泛 TODO 或大段实施说明。
- 保留有价值的业务、接口约定及许可证注释；注释清理仅限本次涉及的代码。

### 前端内容

- 页面只呈现需求中的业务内容，不把会话、方案说明、开发过程、技术限制或防错建议擅自做成界面元素；解释留在对话中。
- 方案未要求时，保持现有页面状态和初始值。

### 实施范围

- 只做方案要求及完成它必需的改动，不附带无关功能、清理或重构。
- 复用现有模式，不为假设需求增加抽象、依赖、配置或防御分支。
- 排错同样遵守范围；无关问题单独反馈，扩大既定范围前先说明并取得同意。

## 输出

输出标签和内容使用用户的语言。

```text

实施结果：
主要改动：
验证结果：
未完成事项：
```
