# amo-detail

## 元数据

- name: `amo-detail`
- description: 当用户希望了解已有方案的整体链路、影响范围、前端变化、后端数据流向、存储或定时任务时使用。侧重方案详情的呈现，不用于初始方案设计、挑战既定方案、直接实施或代码审查。
- version: `0.3.0`

# Amo Detail

从整体链路、影响范围及前后端变化，呈现已有方案的具体情况。

## 共享输出标记

首行内联前缀使用 `🔎 [amo-detail]`。不要把该标记单独放在一个段落里。

## 使用场景

- 已有方案，由用户提供，或通过 `amo-feature`、`amo-improve`、`amo-fix`、`amo-refactor` 或 `amo-best` 形成。
- 用户希望了解整体链路，以及影响哪些功能和模块。
- 用户追问前端会发生什么变化，或后端数据、存储及定时任务如何运作。

## 不使用场景

- 尚未确定方案方向；使用 `amo-feature`、`amo-improve`、`amo-fix` 或 `amo-refactor`。
- 用户希望挑战已有方案；使用 `amo-best`。
- 用户要求编码实施或审查已实现代码。

## 工作流

1. 从讨论中明确已有方案，查看相关代码核实当前情况。
2. 串联从触发到结果的流程，说明影响哪些功能和模块。
3. 说明前端组件复用与改动、显示数据及其来源、状态流转和页面变化。
4. 说明后端处理及数据流向、涉及的数据库表和字段，以及定时任务的执行时间、内容和结果。
5. 按输出结构呈现详情，区分当前行为与方案带来的变化。

## 核心规则

- 沿用既定方案和判断标准，不重新选型。
- 基于讨论和代码说明当前情况，区分已有行为与拟议改动。
- 只展开方案涉及的变化，不为填充输出添加功能、状态或架构。
- 不涉及的部分标明“不涉及”，未确定的细节标明“待确认”。
- 只解释方案，不直接实施；用户要求时再补充实施顺序或验证方式。

## 输出

输出标签和内容使用用户的语言。

```text
🔎 [amo-detail] 场景：方案详情
方案：
- 流程链路：
- 影响范围：

前端：
- 组件复用与改动：
- 数据显示：
- 状态变化：
- 页面变化：

后端：
- 数据流向：
- 数据库变化：
- 定时任务：
```
