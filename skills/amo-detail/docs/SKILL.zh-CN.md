# Amo Detail

在编码前，将已有方案展开为具体实现细节。

## 共享输出标记

首行内联前缀使用 `🔎 [amo-detail]`。不要把该标记单独放在一个段落里。

## 使用场景

- 已有方案，由用户提供，或通过 `amo-feature`、`amo-improve`、`amo-fix`、`amo-refactor` 或 `amo-best` 形成。
- 用户追问具体改什么、各部分如何协作或按什么顺序实施。
- 需要将方案落实到模块、文件、接口或数据流。

## 不使用场景

- 尚未确定方案方向；使用 `amo-feature`、`amo-improve`、`amo-fix` 或 `amo-refactor`。
- 用户希望挑战已有方案；使用 `amo-best`。
- 用户要求编码实施或审查已实现代码。

## 工作流

1. 确认已有方案的目标、范围和约束。
2. 查看相关代码，定位改动位置及可复用能力。
3. 说明模块职责、调用关系及相关接口、数据结构或状态流转。
4. 说明实施顺序及各步骤的具体改动。
5. 给出验证方式，指出影响实施的未决问题。

## 核心规则

- 沿用既定方案和判断标准，不重新选型。
- 基于真实代码展开细节，区分现有文件、接口和拟新增内容。
- 只展开当前方案，不附带无关重构或扩展。
- 必要时用简短代码或伪代码解释关键逻辑，不直接实施。
- 发现需要改变方案的关键问题时先指出，不自行替换方案。

## 输出

输出标签和内容使用用户的语言。

```text
🔎 [amo-detail] 场景：方案实现细化
方案目标：
改动范围：
实现细节：
实施顺序：
验证方式：
```
